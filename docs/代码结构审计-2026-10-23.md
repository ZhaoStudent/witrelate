## 一、结论摘要

### 先说好的

- 12 个角色、10 个部署、2 个软废弃，和 `acps_config.py` 一致。
- 平台身份真实：**法前哨 v1.1.0**，AIC `…6CKYE5.0ZV54U.0IPO`，`APPROVED/active`。
- s1 七个角色 + 体验应用在听，s2 三个证据叶子在听。
- `check_local` 21 节全绿；`verify_experience` 155 项；`verify_metrics` 100 项。
- 每日案例轮已跑到 **23 轮**，最新 10-22/10-23 均 `completed`、`exit_code=0`。

### 真正要正视的

1. **目标与主链默认行为错位**：代码首先是一套“可疑说法事实核查 + 多媒体鉴伪”系统；
   “事前准备/法律方向/回应演练”是主控提示词里的**条件分支**，不是默认主路径。
2. **`FinalVerdict` 仍是真相核查契约**：没有结构化的法律建议字段；
   `action_advice` 在提示词里一处说“不要直接建议行动”，另一处又要求把法律建议写进去。
3. **隐藏牌/手机端只是设计，不是实现**：当前 `experience` 是三桶信息分区
   （`shared/mine/theirs`），没有“声称 / 已打出 / 未打出 / 牌堆”状态，也没有移动端。
4. **外部成效在审计时为 1 次成功，10-23 22:31 增至 2 次**：平台记录里 6 条 s1 侧 completed 是内部自测，
   不是 6 次外部访问；不能混算。
5. **可复现性有缺口**：
   - s2 的 `agents.py`/`acps_config.py` 与 s1/本地不一致（只差主控显示名与注释，叶子不受影响，但版本不干净）；
   - 体验应用的 systemd unit 只在服务器 `/etc/systemd/system`，仓库里没有模板；
   - 文档/PPT 构建脚本在 `tools/*.py` 会被同步，但 `requirements.txt` 没有 `python-pptx`/`python-docx`，项目 `.venv` 里也装不出来。
6. **基线已过期**：`docs/当前事实基线.md` 还写“20 轮 / 下次 10-21”，
   实际 23 轮、最新 10-23；定时器 NEXT 是 10-24。

## 六、发现清单（按优先级）

### P0 · 先处理，但**不要动 ACS/主控提示词**

#### P0-1 目标与主链默认行为错位

**证据**

- `legal_acps/agents.py:390`：主控开头仍是“法律咨询多智能体系统的主控……完成真相研判”。
- `legal_acps/agents.py:550-567`：法律咨询只是“只在用户描述的是自己正处在纠纷初期……且没有要求事实核查或证据鉴伪时才走”的条件分支。
- `legal_acps/contracts.py:228-265`：`FinalVerdict` 字段是 `truth_score/conclusion/action_advice`，没有结构化的 `LegalAdvice`。
- `legal_acps/agents.py:424` 说 `action_advice` “不要直接建议用户采取任何行动”；
  `agents.py:559` 又说法律建议“转述进 action_advice，必须连同能力边界”。
  同一字段两种口径，模型只能自己猜。

**影响**

- 用户问“我遇到这事该怎么办”时，主控可能仍走事实核查，输出一个 `truth_score=50` 的“结论”，
  而不是“法律方向 + 证据清单 + 回应建议”。
- 这不是提示词措辞问题，是**契约没有为产品目标留字段**。

**修复建议**

- **赛前不改**：改主控提示词/`FinalVerdict` 会改变已过审 Agent 的行为与工具 schema，
  需要重新回归甚至重审；当前材料已按“事实核查 + 鉴伪 + 法律方向”口径写完。
- 赛后二选一：
  1. 在 `FinalVerdict` 增加可选 `legal_advice`/`preparation` 字段（需要重审 ACS）；
  2. 不改 ACS，在体验/产品层做“事前准备”编排，主控只负责核查与鉴伪。
- 若必须赛前动，只做**不改 schema**的提示词收敛，并先跑 `check_local` + 真实 e2e；不建议。

**验收门**

```text

check_local 21 节通过
真实 e2e：法律咨询输入 → 必须走 law-advisor，且最终输出包含能力边界
```

## 七、关键矛盾的详细说明

### 7.1 为什么“目标 vs 实现”不是一句话能修

`FinalVerdict` 是已过审 Agent 的交付契约。它现在的字段是：

```text
subject / is_incitement / harm_index / band / truth_score /
consistency_note / conclusion / action_advice / disclaimer
```

它没有：

```text
legal_advice（结构化的法律方向）
cited_articles（法条引用）
evidence_checklist（准备清单）
uncertainty（不确定性分层）
```

所以法律顾问即使返回了 `LegalAdvice`，主控也只能把它压成 `action_advice` 的一段字符串。
这不是“提示词再写两句”能解决的；加字段会改工具 schema、影响 ACS 审核。

**赛前正确策略**：冻结契约，材料里把“法律方向”表述为**主控汇总能力 + 条件分支**，
不宣称“所有输入都走完整法律建议链”。赛后要产品化，再改契约。

### 7.2 隐藏牌为什么不是“界面改一下”

当前 `experience` 的 `InfoPartition` 只有：

```text
shared（双方知道）
mine（只有当事人知道）
theirs（指控方声称掌握、当事人没见过）
```

`theirs` 已经是“声称”，不是“实际手牌”——这点比 v1 桌面稿正确。
但它没有：

- 对方未打出的牌堆（数量未知）；
- “已打出”与“声称”的状态迁移；
- 牌面核验结果；
- 复盘时的实际手牌揭示；
- 手机端布局。

v2 设计文档把这些补上了，但**没有一行实现**。所以：
**不要把 v2 原型当成已实现功能写进答辩材料**；它只能作为“产品化设计/Q&A 备用”。

### 7.3 外部成效的正确数法

| 口径 | 数字 |
|---|---:|
| 平台 inbound completed | 8 |
| 其中内部自测 | 6 |
| 其中外部成功 | **2**（同一外部 AIC） |
| 不同外部 AIC | **1** |
| 外部取消 | 2 |
| 旧 AIC 遗留 inbound | 1（不计新身份） |

“8 条 completed”不能对外说成“8 次外部调用”；也不能说“2 个不同外部账号”。
