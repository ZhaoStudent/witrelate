# 整改清单（11 项）

> 这份清单是给**作者本人**看的，不是给评委看的。目标：把已经做出来的技术资产，
> 变成**可提交、可答辩、可复现**的作品。
>
> 用法：从上到下做；每项都有“验收物”，**没有验收物就不算完成**。
> 当前事实以 [当前事实基线](当前事实基线.md) 为准；本清单每周更新一次状态。
>
> 三条原则：**不新增 Agent、不重构、不追求每项满分**。
> 先锁分（材料/外部访问/合规），再补证据（评估/演示），最后还技术债。

**如果你今天只看三件事：**

1. **发邀请**（今天，30 分钟）——把外部访问从 1 往上做；
2. **10 页报告 + 5 分钟视频**（两周）——所有分的载体；
3. **干净 release**（一周）——评委能自己跑起来。

其余 8 项都是为这三件服务的；不要同时开工。

## 执行顺序（按这个顺序做）

### 今天（T0）

1. **#2 外部邀请**：把三条文案发到赛题群 / 交流群 / 3–5 位同学（见
   [外部邀请-发送清单](外部邀请-发送清单.md)）。
2. **#9 脱敏**：确认公开材料不出现学校名；把手册里的真实口令换成占位符并轮换；
   线索数据加“保留期限/脱敏/删除”三句话。
3. **#3 收尾**：把 `README.md` 和 `当前事实基线.md` 的事实核对一遍；
   给旧文档加日期横幅（已完成 3 份）。

**T0 验收**：邀请已发出（截图/时间）；仓库里搜不到明文口令；根 README 能让人 3 分钟看懂。

### 第 1 周（T0+1 ~ T0+7）

4. **#1 报告骨架**：先写 10 页，不追求文采：
   ① 问题（一条真实谣言/诽谤的处置链）② 架构图 ③ 复用/自创模块表
   ④ 平台接入与跨机证据 ⑤ 评测口径与数字 ⑥ 不足与未来工作。
5. **#8 release**：根 README 的 quickstart 在干净目录跑一遍；
   补 LICENSE/NOTICE；把 `run/` 的探针移出交付包；写 `demo.sh`。
6. **#1 视频脚本**：5 分钟分镜，只讲一个案子：
   “一条说法 → 发现裁判 → 辩论/快车道 → 证据鉴伪 → 法律建议 → 溯源表”。

**第 1 周验收**：报告 5 页以上；干净目录 `stub` 能跑；视频脚本 1 页。

### 第 2 周（T0+8 ~ T0+14）

7. **#4 holdout**：选 20 条**库外**新案，先冻结再跑；报告里同时报
   准确率、弃权率、失败类型；把 0/13→21/22 的“补值域/扩库/重标”拆开讲。
8. **#10 演示彩排**：按视频脚本走一遍；准备 Plan B（stub 录屏、本地样本、
   平台截图）；确认 timer 和常驻服务在演示前 30 分钟健康。
9. **#1 视频/PPT 定稿**：录 3–5 分钟；PPT 转 PDF；截图打码（校名/个人信息）。

**第 2 周验收**：20 条 holdout 有结果；彩排 2 次无阻断；视频/PPT 初稿。

### 最后（提交前）

10. **#6 / #5 / #7 / #11**：只做“报告里能写清楚”的最小动作：
    - #6 加 name allowlist（半天）；
    - #5 改措辞（半小时）；
    - #7 二选一：接通一次证据核验，或明写“体验层不进 ACPs”（半天）；
    - #11 冻结新增，模块图已落（[ARCHITECTURE.md](../ARCHITECTURE.md)），不重构；
11. **提交前回归**：`check_local`、`acs_fingerprint`、`verify_experience`、
    前端 52 项、平台截图、`output/` 最新产物；全部留一条命令输出。

- 不要把“跳过”写成“通过”，不要把“邀请过”写成“调用过”。
