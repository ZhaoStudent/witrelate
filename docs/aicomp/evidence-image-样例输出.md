## 5. 复检路径（`upgrades`）—— 交付给用户的「更准但更贵」选项

这是本能力对用户最核心的产出：**本地初检免费且秒级，但它只能给线索；
要出可举证的结论就必须升级**。以下为程序按成本递增生成的完整清单：

> ⚠️ 这份清单一律**完整给出，不随线索等级裁剪**。早先按等级裁剪（低→前 2 条）时，
> **「线下司法鉴定」在最常见的「低」里被静默删掉了** —— 而它是唯一有法律证明力的路径。

- **online_free ｜ C2PA Content Credentials Verify / Google SynthID** — 成本：免费 ｜ 时限：秒级
  - 何时值得用：**先做这一步**。若图像带 C2PA 签名且签名有效，可得到接近确定的来源结论；但注意「没有签名 ≠ 是假的」—— 截图、转存、平台压缩都会剥掉签名。
- **online_paid ｜ Hive Moderation / Optic (AI or Not)** — 成本：有免费额度，付费约 $29–199/月起 ｜ 时限：秒级～分钟级
  - 何时值得用：需要快速批量筛查、或要识别**具体是哪个生成模型**时使用。
- **online_paid ｜ Truepic / deepidv 等逐次计费 API** — 成本：Truepic 约 $0.02/次；deepidv 约 $0.50/次 ｜ 时限：分钟级
  - 何时值得用：单张图需要一份**可留存、可复核**的第三方检测报告时使用。⚠️ 厂商自报准确率 96–99%，但独立测评显示顶级检测器仍有 15–20% 假阴性。
- **offline_forensic ｜ 声像资料司法鉴定（图像真实性鉴定）** — 成本：约 2500–4000 元/组（发改价格规〔2020〕1632 号） ｜ 时限：一般 30 个工作日
  - 何时值得用：**涉及法律责任时唯一有证明力的路径**。须委托省级以上司法行政机关登记在册、业务范围含「图像鉴定」或「电子数据鉴定」的机构，并提交**原始载体**（只读介质、保留序列号）—— 所以原始文件现在就要保全，事后无法补。

## 6. 证据保全与免责

- `chain_of_custody`：
  - 立即保全**原始载体**（原始存储卡 / 手机 / 只读镜像），不要用微信、截图、转发件转存。
  - 对原文件计算 SHA-256 并记录时间与操作人；本次报告的 sha256 字段即为该值。
  - 任何后续取证都在**只读副本**上进行，原件封装保存 —— 司法鉴定通常要求提交原始载体。
- `disclaimer`：本报告是基于公开图像取证方法得出的**技术线索**，不是司法鉴定意见，不能单独作为认定事实的依据。所列「未提示异常」**不等于**该图真实；所列「提示异常」**不等于**该图伪造 —— 例如平台重压缩、裁剪、降噪、格式转换都会产生同类痕迹。如需具备法律效力的结论，请走司法鉴定路径。

理由不是好看 —— 调用方（模型）收到一句不透明的异常时，最可能的反应是

`status=refused` + `refusal_reason` + `how_to_fix`：

|---|---|---|
| 出网但未配白名单 | `未配置白名单，禁止出网取图（这是默认行为，不是故障）。请设置 EVIDENCE_IMAGE_ALLOWED_HOSTS=<逗号分隔的主机名> 后再试。` | 请让管理员设置 EVIDENCE_IMAGE_ALLOWED_HOSTS=<逗号分隔的主机名>，或改传 data:image/...;base64,... 形式的自带字节。 |
| 明文 http | `拒绝明文 http 取图 —— 明文链路上的图片无法保证未被中途替换。` | 改用 https 地址。 |
| 本地文件（默认禁止） | `拒绝读取本地文件（file://）—— 本入口默认关闭它，因为打开后它就是一个「任意本地文件读取」原语。如需在单机自测 / 演示里读取，只能由入口代码调用 fetch.enable_local_file() 显式打开（刻意不提供命令行开关与环境变量：两者都会被服务进程继承，纪律守不住）。` | 把图片作为任务附件提交（走 inbox 句柄）；如需在本机自测中读本地文件，须在启动入口显式开启。 |
| 伪造 / 未登记的收件箱句柄 | `收件箱引用无效：收件箱里没有 000000000000… 这份字节 —— 可能不属于本次任务，或已被清理。` | 这个 inbox: 句柄在本进程里没有登记过 —— 请确认它是本次任务附带的图片（可直接引用系统给出的句柄原文），不要自己拼一个哈希。 |
| 声明是图片、字节是垃圾 | `无法对这张图完成初检：不是可识别的图像容器（按魔术字节判定为 application/octet-stream）` | 传给 image_uri 的字节不是图片：请确认给的是**图片文件本身**的字节，而不是网页、PDF、或一段文字。 |
| JPEG 只有文件头（截断） | `无法对这张图完成初检：Truncated File Read` | 请确认提交的是**完整、未截断的原始图片字节**；若这张图本身已损坏，请改用能正常打开的原始文件重新提交。 |
| 超大图（只有文件头、无像素数据） | `无法对这张图完成初检：图像像素数过大（12000×10000 = 120 MP，上限 100 MP）—— 请先等比缩小再传。` | 请先**等比缩小**到 1 亿像素以内再提交（解压超大图会占满服务器内存，连带影响其它角色的可用性）。 |

> ⚠️ 最后三种**不是策略拒绝，而是输入本身不可用** —— 它们曾经会**直接抛异常**穿透出去。
> 补救建议也必须分清是谁的责任：输入不可用时写「请确认给的是图片本身的字节」，
> 而不是兜底成「请联系管理员」—— 后者会把一个五秒钟能改对的问题变成一次没人能处理的上报。
