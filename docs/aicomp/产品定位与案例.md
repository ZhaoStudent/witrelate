# 产品定位与案例（草稿）

> 这份文件解决一个很具体的问题：**你做的不是“遇到官司再问律师”，而是“遇到法律问题之前先做准备”。**
> 所以对外名称、案例、视频脚本都不该围绕“咨询”，而该围绕「事前 / 预演 / 准备」。
>
> 平台上的主控 Agent 已于 2026-10-21 改名为 **「法前哨」**（v1.1.0，新 AIC
> `…6CKYE5.0ZV54U.0IPO`）；作品名、报告标题、视频旁白统一用「法前哨」。

---

## 1. 一句话定位

**在转发、回应、签约、找律师之前，先做一次法律预演。**

不是“帮你打官司”，而是“帮你在成为当事人之前，把事实、证据、话术和法条准备好”。

---

## 2. 五个案例（从轻到重）

### 案例 A · 家族群里的“爆炸视频”（转发前）

**场景**：亲戚在群里发“某地烟花厂爆炸，2 死 2 伤”的视频，配文“快看，太惨了”。你半信半疑，但不想误转。

**用户动作**：把视频和说法交给系统。

**系统做什么**：

- `fact-judge`：核查“某地是否发生爆炸”这一命题；走快车道或辩论道；
- `evidence-leader`：对视频做容器/帧/时间线初检，对关键帧做图像鉴伪；
- `law-advisor`：说明转发虚假灾情可能触及的法律边界（覆盖范围内），以及“转发前该核什么”。

**产出**：一份裁定书 + 一份证据技术线索 + 一段“转不转、怎么转”的建议。

**为什么是好例子**：几乎每个人都有家族群；它同时展示事实核查与证据鉴伪，且不需要真实个人数据。

---

### 案例 B · 被人挂了“聊天记录”（回应前）★ 旗舰案例

**场景**：有人在群里发了一张聊天记录截图，指控你“收了好处/说了某句话”；截图看起来像真的，群里已经开始站队。你还没回应。

**用户动作**：把指控原文、截图、自己的时间线交给系统。

**系统做什么**：

1. `lead-intake`：把指控规范成一条待核查线索（不预设真假）；
2. `evidence-leader` + `evidence-image`：检查截图是否有复制-移动、EXIF/压缩异常、拼接线索；
3. `fact-judge`：把“截图是否可信”与“指控是否成立”分开；必要时组织正反辩论；
4. `law-advisor`：在《民法典》人格权/名誉权与《刑法》相关条文范围内，给出“该固定什么证据、该不该找律师、先别做什么”的方向；
5. `experience` 演练场：让你先和“带节奏的人”过一招，揭示对方用了哪些话术、你哪里被带偏；
6. `trace`：把“谁在什么时候、用哪个 Agent、得出了什么”串成一张溯源表。

**产出**：证据线索 + 裁定 + 法律方向 + 一次回应演练 + 可回溯的链路。

**为什么是好例子**：它同时展示“事实、证据、法律、话术、溯源”五件事，而且完全发生在“成为当事人之前/之初”。

---

### 案例 C · 签租房/借款合同之前（签字前）

**场景**：你要签一份租房合同或借款协议，不确定哪几条要警惕，也不想为这点事直接找律师。

**用户动作**：把关键条款**贴成文本**（系统不读 PDF），说明自己的处境。

**系统做什么**：

- `law-advisor`：在《民法典》合同编范围内，指出可能的权利/义务、需要保留的证据、下一步方向；
- 超出八部法律库覆盖范围时，如实说“这块我覆盖不了”，而不是硬编法条。

**产出**：一份 `LegalAdvice`：事实复述、适用性、建议清单、逐字法条引用、能力边界、免责声明。

**为什么是好例子**：非常日常；同时展示“法条必须逐字可核验”和“能力边界诚实”。

---

### 案例 D · 找律师之前的一页纸（咨询前）

**场景**：事情已经发生，你准备去找律师，但不知道该带什么、该问什么。

**用户动作**：把时间线、聊天记录、转账记录、对方说法交给系统。

**系统做什么**：

- `law-advisor`：梳理事实、可能的法律关系、需要固定的证据、建议问律师的 5 个问题；
- `trace` / 台账：把材料来源和时间线固定下来，避免“到了律所才发现少了一张图”。

**产出**：一页“案情 + 证据 + 问题清单”，不是法律意见书。

**为什么是好例子**：它把“法律咨询”变成“咨询前的准备”，正好避开“AI 给法律意见”的合规风险。

---

### 案例 E · 短视频发布前（发布前）

**场景**：你拍了一条涉及他人门店/纠纷的视频，准备发出去；担心画面被说“剪辑过”，也担心侵犯名誉/肖像。

**用户动作**：把视频/图片和文案交给系统。

**系统做什么**：

- `evidence-leader`：对视频/图片做技术线索初检（剪辑点、容器、帧层）；
- `law-advisor`：在覆盖范围内提示名誉/肖像/隐私风险，建议打码、取证、保存原始文件。

**产出**：技术线索 + 发布前检查清单。

**为什么是好例子**：适合创作者群体，且“发布前”是典型的事前场景。

---

### 备选 · 社区/班级反诈演练（被带节奏前）

`experience` 演练场：5 分钟一局，用户扮演被指控的当事人，和“诱导方”过招，结束后裁判揭示 4 类证据话术 + 6 类修辞话术，并做信息差复盘。适合社区普法、班会、培训。

> 注意：演练场是**进程内编排**，不注册 ACPs，不产生平台访问记录；材料里要如实标注，别把它算进“平台访问量”。

## 3. 旗舰案例的分镜（5 分钟视频）

以案例 B 为主线，按这个顺序拍：

| 时间 | 画面 | 旁白/字幕 |
|---|---|---|
| 0:00–0:30 | 群聊里一张截图 + “他收了好处” | “一条指控、一张截图，在群里传开。你还没回应。” |
| 0:30–1:00 | 受理官把问题拆成“待核查命题 + 事实清单” | “先别急着自证——把问题拆成可核查的命题。” |
| 1:00–1:45 | 证据官跑图，出现复制-移动/EXIF 线索 + caveat | “截图是不是原图？技术线索先说话，但不做定性。” |
| 1:45–2:45 | 裁判组织正反辩论 / 快车道 | “听双方把话说完，再裁。” |
| 2:45–3:30 | 法律顾问给出法条 + 行动方向 + 边界 | “能引的条文逐字引，不能覆盖的如实说。” |
| 3:30–4:15 | 演练场：用户 vs 诱导方，揭示话术 | “先练一遍，再决定怎么回。” |
| 4:15–5:00 | 溯源表：每个结论对应哪一跳 | “每一步都留痕，结论才可回溯。” |

## 5. 作品简介草稿（≤300 字）

> 很多人不是输在官司里，而是输在事发前：转了一条假消息、信了一张改过的图、在群里说错一句话、该留的证据没留。法前哨是一套运行在梧桐 ACPs 平台上的多智能体事前准备系统：受理官把问题结构化，网络裁判组织正反辩论并核查事实，证据官对图片/音频/视频做技术鉴伪，法律顾问在覆盖范围内给出法条依据与行动方向，演练场让你先和“带节奏的人”过一招。每一步都留痕，最后生成一份可回溯的准备清单。它不做法律定性，只帮你在成为当事人之前，先把事实、证据和话术准备好。

（约 240 字，可再按报名系统字数微调。）

## 6. 一句提醒

案例要“事前”，但**结论不能写成法律定性**：

- 说“存在与 X 一致的线索”，不说“这是伪造的”；
- 说“在《民法典》范围内可考虑……”，不说“你一定能赢”；
- 说“建议咨询执业律师”，不说“建议你起诉”；
- 说“本次没跑成 X 项”，不说“没问题”。

这四条既是合规边界，也是这个产品最像“专业工具”的地方。
