5. **未揭示的会话无法结束。** `assert_revealed()` + `/close` 未揭示返回 **409**。

## 2 逐条评价

### 2.1 「网络裁判一定要少与用户说话」→ ✅ 已满足，而且比你要求的更彻底

**判据（可直接复验）**：

```
grep -n "_judge" legal_acps/experience/session.py
→ 31（import）、141–142（构造）、211（reveal）三处
```

`start()`（开局）与 `reply()`（每一轮交锋）里，裁判**一次都没被调用过**。
对局界面上裁判从不发言，只是链路图上的一个节点。你要的效果已经成立。

**但有一条不能省：揭示环节必须留着。** 理由是它不是"裁判多说话"，而是：

1. 它是**这个产品的交付物** —— 用户带走的就是那份复盘；
2. 它是**红线②的落点**：`assert_revealed()` + `/close` 返 409，少了它这个应用就从
   "反诈教育"变成"真的在误导人"。

所以正确的表述是：**裁判在对局中沉默，只在对局前后各开口一次。**
这句话本次已经写进了 `JUDGE_INSTRUCTIONS` 的开头，防止后来者（或模型）把它理解成
"裁判应该多点评几句"。

### 2.2 「正反方出示图像、声音、视频」→ ⚠️ 可行，但有三道坎

**坎① 模型看不见图。**

`legal_acps/llm.py` 用的是 `OpenAIChatProvider`（文本 `/chat/completions`），
项目里**所有 Agent 都是文本链路**。而现有的鉴伪是**确定性代码**算出来的
（`evidence/forensics.py`，Pillow + numpy），模型只负责"组织与解释" ——
`EVIDENCE_IMAGE_INSTRUCTIONS` 里明写：

> 「**不要**自己尝试下载、解码或"描述"这张图 —— 所有判定都由确定性代码算出。
> 你的职责是**组织与解释**，不是替代检测。」

**这反而是可行路径**：**媒体不进辩手的上下文，进的是鉴伪线索。**
辩手"出示证据" = 出示一条**证据引用**（句柄 / 地址）+ 它的鉴伪结论。
辩手不需要"看见"那张图，它需要的是"这张图有哪些技术线索"。

**坎② 声音 / 视频鉴伪根本不存在，而且是重依赖。**

`legal_acps/evidence/` 下只有图像。音视频初检要 ffmpeg + 解码器（视频还要关键帧/音轨分离），
而且项目有一条既成原则：**纯文本链路不引重依赖**
（`evidence/__init__.py` 的延迟导入注释就是为了防止"服务器没装图像库 → 6 个已过审 Agent 全部起不来"）。

**建议**：图像先行；音视频分成两级 ——
- 先做**容器 / 元数据级**初检（纯字节解析，不需要解码器，零重依赖）：容器类型、
  创建/修改时间、编码器字符串、时长、码率、有无剪辑软件的写入痕迹；
- 真正的信号级检测（重压缩、音轨拼接、深伪）写进"未来工作"。

**坎③ AIP 工具层只给 `uri`，字节必须由代码塞。**

已实测（前轮）：模型工具层的 `TOOL_CONTENT_INPUT_SCHEMA` 只暴露 `uri`
（`required: [type, uri, mime_type]`），所以**模型委派只能给 URL，字节只能由代码塞**。
图片这条路已经用 `EvidenceInboxHooks` + `inbox:<sha256>` 句柄解决了；
音视频要照做一遍（收件箱 + 句柄 + 代码注入）。

### 2.3 「正反方也能调用鉴伪 Agent」→ ⚠️ 会撞上你自己的链深熔断

**事实一：两位辩手是叶子。** `build_debate_pro` / `build_debate_con` 都**没有**挂
`AipDelegationHooks`，提示词里也明写「你**不再向下委托** —— 你在委托链的下游」。
它们根本没有 `acps_delegate` 这个工具。

**事实二：链深上限是 3。** `contracts.py:449  MAX_CHAIN_DEPTH = 3`。

于是"辩手直接调鉴伪"的链是：

```
leader(1) → fact-judge(2) → debate-pro(3) → evidence-image(4)   ✗ 超过上限 3
```

这不是"实现不了"，而是**会撞上你自己正在讲的机制** ——
链深熔断 + 环检测是你写在创新性里的东西，**放宽它等于自己拆掉一条**。

| 选项 | 形态 | 代价 |
|---|---|---|
| **A（推荐）** | **鉴伪由裁判统一代调**：辩手在论证里写"申请鉴定（证据 + 理由）"，裁判调鉴伪，线索回到双方 | 链深 = 3 ✓；符合 AIP §3.2「Partner 之间不直接交互」；且**保住裁判的中立性**（鉴伪结论由中立方引入，不会被某一方选择性使用） |
| B | 辩手直接调 | 必须把 `MAX_CHAIN_DEPTH` 提到 4；`verify_termination` / `check_local` 里的成对断言要跟着改；创新性叙事要重写 |

**⚠️ 还有一个更关键的岔路，比 A/B 更重要：**

体验应用是**进程内编排**，不是 ACPs。`session.py` 顶部注释解释得很清楚 ——
它必须"**等人**"，而 ACPs 的任务是"一次 run 跑完就结束"，中途没有等人输入的位置。

推论：

- 如果鉴伪在体验应用里发生，它是**进程内函数调用，不是 ACPs 调用** →
  **不产生跨智能体访问记录** → 对"平台访问次数""互联交互存证"**零贡献**。
- 若想让这次操作**同时喂两条战线**（教学 + 存证），就得让体验层调用的
  `evidence-image` 是**平台上真实注册的那个**（体验层的受理官/诱导方/裁判仍是进程内的）。

**这是我这次最想让你注意的一条：同一次操作可以同时是"教学"和"存证"。**
它同时补给：应用成效（10 分）、附加分③（访问量排行榜）、P0 一票否决线的"访问"环节存证、
以及演示视频的素材。

### 2.4 「正方扮演坏人、不择手段」→ ⛔ 不建议放开；给出可以放开的正确方向

**三条理由：**

1. **平台合规。** 这些 Agent 准备注册在 `ioa.pub`，ACS 里
   `provider.organization = BUPT-LegalAgent-Demo`。生成**真实的**诽谤内容 = 账号与作品双重风险。
   而且这正好反向踩在你在讲的"交互安全管控"上 —— 你在 A 面证明自己能拦外部 Agent，
   在 B 面却放一个会真的造谣的 Agent。
2. **教学反效果。** 现有提示词里已经写了这条判断：

   > 「**一两条就够，不要每条都用满** —— 现实中带节奏的人也不会一次露所有破绽，
   > 那样反而假。你的目标是"让他隐隐觉得不对劲，但说不上来哪里不对"。」

   全用满的话，"揭示"会变成一堵墙：用户记住的是"我被骗了"，而不是"我认得出来"。
3. **红线是产品前提，不是装饰。** 不针对现实中具体个人 / 不教唆违法 / 不戳破第四面墙 ——
   这三条一旦松开，这个应用就失去了存在理由。

**✅ 可以放开的正确方向：给话术加一层「修辞层」。**

现在的四类是**证据层**话术 —— 它们回答"材料被动过没有"：

```
① 时间错配   ② 断章取义   ③ 张冠李戴   ④ 数字夸张
```

而网上带节奏更常见、也更难防的是**修辞层**，它**根本不碰事实**、
专门攻击你的认知与情绪：诉诸情绪、滑坡、虚假二分、稻草人、诉诸权威、举证责任错置。

**加"修辞层"才是你要的"各种话术"，而且零法律风险**（修辞层不涉及伪造事实）。

**指纹核实（实测，决定这一步能不能做）：**

- `FallacyKind` 的取值**不出现在任何 ACS 字段里**。
  实测：`时间错配` / `张冠李戴` / `数字夸张` 在 `.wit/*/acps/*.json` 中命中 **0**；
  `断章取义` 命中 1，但那是 `fact.issue_ruling` 描述里的 **`RulingVerdict`** 值，不是 `FallacyKind`。
- ACS 的 `skills[]` 结构是
  `{id, name, description, tags, inputModes, outputModes, version}` —— **没有输入 schema**。
  （`capabilities` 是 `{messageQueue, notification, streaming}`，与枚举无关。）

→ **新增枚举值 = 只改工具 schema = 不改注册指纹、不需要重新过审。**

**✅ 这条已在本次改动后实测确认**：用新建的 `tools/acs_fingerprint.py` 比对改动前后，
**7 个角色的指纹全部一字未变**（见 §4 的关键取证）。

> ⚠️ 但"不改指纹"不等于"什么都不用做"：**对外工具 schema 变了**，
> 6 个已注册角色的服务要**重启**才会下发新枚举。

**✅ 本次已落地**（`FallacyKind` 4 → 10 类，两层各有分层常量与助手函数；
提示词清单改为**由枚举派生**；复盘页按层分组，且分层由服务端算 —— 见 §4）。

⚠️ 两条约束必须守着（本次都踩到了，记下来）：

1. **新话术名不许写进任何 `@capability(description=...)` 或 `tags`** —— 那两处进 ACS，改了就换指纹。
2. `tools/verify_experience.py` 里那条 **`check("话术类型恰为四类", kinds, {...})` 是精确相等**的断言，
   不改第一步就红；`legal_acps/check_local.py` ③ 里还有一条同样的精确相等
   （它报出来的失败信息是「话术类型缺失：**[]**」—— 缺失集是空的，
   明明是"多了"却说"缺了"）。**两条都已改成"至少包含"**，并新增"每类必须归层"。

### 2.5 「用判断与事实判断的差异强化学习」→ ⚠️ 术语要换，机制可以落地

**先说缺什么：** 没有奖励信号、没有策略更新、没有训练循环。
`llm.py` 是固定的 `OpenAIChatProvider`（`temperature=0`），没有微调管线。
**评委问一句"你的奖励函数是什么"就答不上来。**

**你真正要的是「校准」** —— 让"置信度"与"证据充分度"对齐。而校准的第一条地基你已经打好了：

- `RulingVerdict.UNDECIDABLE = "无法判定"`；
- `FACT_JUDGE_INSTRUCTIONS` 明写「**「无法判定」是合法且经常正确的答案** —— 证据不足时给结论比给错更糟」；
- `FactRuling.confidence` 的描述是「证据强度，诚实反映；来源互相矛盾时它就是上不去的」。

**「敢说无法判定」就是校准的地基** —— 这是一条能写进材料、且真实存在的东西。

**可落地的形态（零新增依赖、离线可复现）：`tools/calibration.py`**

从 `output/ruling-*.json` 汇总：`verdict` 分布 / `confidence` 分布 / `fallacies` 命中数 /
`confidence` 与 `basis` 条数的关系，输出置信度校准曲线的原料
（把 (confidence, 证据是否充分) 分桶）。它和"**立场对调双跑实验**"共用同一批裁定书 ——
**一份材料两处用**。

**建议措辞**：不要写"强化学习"，写「**判定校准台账**」或「**置信度标定**」，
并明说当前是"离线统计 + 提示词迭代"，不做在线训练。这样评委问不倒你。

## 3 「文字冒险游戏」这个形态的判断

### 3.1 好处（判断，理由如下）

1. **把"识别话术"从知识变成肌肉记忆。** 普法最大的毛病是"看的时候都懂，遇到的时候想不起来"。
   只有被同样的手法当面绕过一次，才会形成条件反射。
2. **它天然产生可量化的教学结果**（第几轮被带偏 / 命中哪几类 / 哪几句站住了）——
   这正是"应用成效 10 分"要看的东西。
3. **它复用你已有的资产**（四类话术 + 三态裁定），不是另造一套。

### 3.2 但严格说，现在还不是"游戏"：缺四个要素

| 要素 | 现状 | 建议 |
|---|---|---|
| **目标** | 无（只是"辩到底"） | "+2 举证成功" / "抓住 2 处话术" |
| **回合结算** | 只有轮数 | 每轮回一句中性的"这一轮对方用了什么 / 你哪里漏了"（不能剧透 `traps`，见红线） |
| **难度阶梯** | 无，固定 | L1 只用 1 类 → L3 组合使用 + 加大施压 |
| **结局分叉** | 只有一种（揭示） | 站住 / 被带走 / 说服对方 —— **但任何一种都必须走到揭示**（红线②不可动） |

### 3.3 第一人称：改动很小，收益很大（**本次已落地**）

差别只在一句话：

| | 原先 | 现在 |
|---|---|---|
| 输入 | 「你看到一个说法」 | 「**有人这么说你**」 |
| 命题方向 | 那个说法是否成立 | **对方对你的指控**是否成立 |
| 用户位置 | 旁观鉴定者 | **当事人**（正方 = 指控方 = 他现实里要面对的人） |
| 带走什么 | "我学会识别谣言的套路" | "**下次有人这么说我，我知道怎么接**" |

这个改动的价值在于它接上了你第三阶段的"被假证造谣"，也接上了你自己的经历。

⚠️ **一条容易搞反的地方**：命题的主语必须是"他"、方向必须是"对方在指控他"。
写成"他被冤枉了"，辩论就变成演戏（信息隔离失效），而且整个体验会从
"演练"滑向"教人怎么造谣"。这条已经写进 `INTAKE_INSTRUCTIONS` 与 `JUDGE_INSTRUCTIONS`。

### ✅ 甲、乙已落地（2026-10-01 夜，用户拍板「甲补实现、乙接线」）

#### 甲：裁判「立题」—— 从"承诺"变成"实现"，而且刻意**分成两层**

补实现时做了一个切分，这是本轮最重要的设计决定：

| 层 | 判什么 | 谁判 | 为什么 |
|---|---|---|---|
| **结构性** | 空命题 / 疑问句 / 价值判断 / **方向倒置** / 事实清单为空 | `experience/opening.py` 的**纯函数** | 这些**有客观答案**，交给模型只会引入不确定性 —— 而"方向倒置"是整个体验**唯一**的把关点；且纯函数能离线穷举（"只有模型才能跑的逻辑，离线验不了等于没验"） |
| **语义性** | 这道命题值不值得辩 / 材料够不够 | 裁判模型（`case.open`） | 只有它能判 |

- 新增契约 `CaseOpening`（`worth_debating` / `sufficiency`(Literal 三档) / `gaps` / `note`）与能力 `case.open`；
  `build_judge` 现在挂**两个**能力（`case.open` + `case.reveal`）—— 少任何一个都回到旧形态。
- `start()` 流程变为 **受理 → 守门 + 裁判立题 → 诱导方开场**；
  `SessionState.opening = {"checks": [...], "judge": {...}|None}`。
- **立题失败不阻断开局**（与受理环节刻意不同：受理拿不到结论就真的没法辩），
  但也**不假装成功** —— `judge` 保持 `None`，前端显式显示
  「裁判**未给出**立题意见 —— 本局照常进行，但这一环没有把关」。
- 前端 `renderOpening()` 把两层**分开呈现**：合成一条就分不清"这条是程序判的还是模型判的"，
  出问题也不知道该查哪边（前者查代码，后者查提示词与模型）。

#### 乙：`group_fallacies` 接线 —— 顺便挖出一个真缺陷

它在被接线时**根本接不上**：旧实现是 `getattr(hit, "kind", hit)`，**只认模型对象的 `.kind`**；
而编排层手上是 `model_dump` 过的 **dict** ⇒ 取不到 kind ⇒ `fallacy_layer()` 返回空串
⇒ **每一条都被静默归到「未归类」**。不报错、链路全绿，用户只是看到所有话术挤在同一个组下面。

> **这才是它沦为死代码的根因：不是没人想用，是用不了。**

修法：`_fallacy_kind_of()` 同时支持两种形态；`FALLACY_LAYER_UNKNOWN` 让未归类**单独成组、显式暴露**；
`_group_traps` 改成**纯委托**（只做 dict→list 的形状转换）。
断言用**关系判据**而不是"输出像不像"：**改了 `contracts` 的层定义，编排层的输出必须跟着变** ——
自己再写一份的实现不会跟着变（那正是它过去当死代码时的样子）。

### ✅ 真机第二抓：揭示失败的**真正原因**是 token 被思考吃光

上面那条"工具挑错"是**第一个**真缺陷。修完之后复跑真机，揭示**仍然偶发失败**，
而 `last_run` 诊断给出决定性的一行：

    {"tool": "case_reveal", "attempts": [
       {"status": "completed", "iterations": 1, "max_steps": 12, "tools_seen": []},
       {"status": "completed", "iterations": 1, "max_steps": 24, "tools_seen": []}]}

`iterations=1`（第一步就结束）+ `tools_seen=[]` + `final_text_len=0`
—— **和步数预算毫无关系**（`max_steps` 加到 24 也一样）。
这个诊断**把"预算不够"这个假设自己否掉了**，指向另一个方向。

**根因**：`llm.py` 早把这条失效模式写在自己的 docstring 里了 ——
「若 `max_tokens` 给小了，token 会被思考过程吃光，content 会是空字符串
—— 表现为『模型没输出』」。而 `DEFAULT_MAX_TOKENS = 8192` 是**全局写死**的，
没有按环节区分。揭示那一轮要通读全场交锋记录 + 话术 JSON，**上下文远长于其它环节**；
5 轮交锋比 3 轮更长 ⇒ 它成了**唯一**会偶发"空输出"的一环。

**决定性证据**（服务器真机，`run/probe_token_budget.py`）：

| 本次请求的 max_tokens | 正文 | 思考 |
|---|---|---|
| 沿用默认 8192 | 2790 字 | 2649 字 |
| **给 64** | **0 字** | 113 字 |
| 给 16384 | 2798 字 | 5926 字 |

"给 64"那一行**精确复现了故障现象**：思考把预算吃光 ⇒ 正文为空。
⇒ `settings["max_tokens"]` **确实透传到了模型服务**（`settings` 的非保留键原样透传给 SDK），
所以"按环节给 token"这条路是通的 —— 这不是推测，是**可复现的行为差异**。

⚠️ 这一步**离线无论如何验不了**：假模型不看 token，写不进去也不会报错 ——
"参数塞进了 request" 与 "模型真的按它执行" 是两件事。所以专门留了
`run/probe_token_budget.py` 作为探针（需 `.env`，只能在服务器跑）。

**修法**：

| # | 改动 | 依据 |
|---|---|---|
| 4 | `session.py` 新增 `REVEAL_MAX_TOKENS = 16_384`，`_run` 增 `max_tokens` 参数；`tool_scope.py` 按 `metadata["experience.max_tokens"]` 写进本轮 `request.settings` | 揭示是**唯一**上下文长到会把 8192 吃光的环节 |
| 5 | `_run` 重试时**两项预算同时翻倍**（步数与 token） | 重试若只翻步数、不翻 token，就是拿同一种资源再试一次同样的失败 |
| 6 | 揭示失败**不再报废整局**，改为**降级 + 显式标注** `judge_ok: False`：三节（hot_spots / solid_moves / advice）留空并说明原因，但**服务端自己算得出的**部分照给 —— 诱导方逐轮自曝的真实话术清单（退到 `traps_all`）+ 当事人的自我标记对照 | 用户已经聊完 N 轮，最后一步报废等于把前面的工作全扔掉。⚠️「降级」绝不能变成安静的常态 ⇒ `judge_ok=False` 是**显式标记**，前端把提示**顶到最上面** |

**元验证又逮到一条"看起来绿"的断言**：探针 ⑧（揭示退回共用默认 token 预算）
第一版报了"空转"—— 原来那条断言写成了**常量自比**
`REVEAL_MAX_TOKENS > DEFAULT_MAX_TOKENS`：把调用处的 `max_tokens=REVEAL_MAX_TOKENS`
删掉，常量自比照样成立，而揭示又回到 8192。**这正是本项目最忌讳的
"参数接对了 ≠ 被用上了"。** 改成断言**揭示实际交付的那个值**（从 `_run` 的 spy 上取）后，
探针 ⑧ 转为有效。
