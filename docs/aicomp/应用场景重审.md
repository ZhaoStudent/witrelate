## 1 现有系统的事实盘点（不是猜的）

**7 个 Agent，唯一一条链：**

```
legal-consult-leader（法律咨询主控）
  ├─ incitement-detector  煽动性识别 + 断言真伪拆解
  ├─ harm-assessor        社会危害性评估（harm_index -100..100，六维）
  ├─ fact-judge           网络裁判（立题 → 组织辩论 → 裁定书）
  │     ├─ debate-pro     正方
  │     └─ debate-con     反方
  └─ evidence-image       图像鉴伪（**尚未注册**）
```

**唯一的对外契约是 `FinalVerdict`**，字段只有这九个：

```
subject · harm_index · band · is_incitement · truth_score
consistency_note · conclusion · action_advice · disclaimer
```

**两句写在提示词里的关键口径**（这是本次审视的核心证据）：

1. `LEADER_INSTRUCTIONS` 汇总原则原文：
   > 「`action_advice` 用词要克制……**不要直接建议用户采取任何行动**。」
2. 同一条提示词的责任边界原文：
   > 「你给出的结论是**辅助研判**，不是法律定性……最终定性权在司法机关。」

另有两处既有资产，后面会反复用到：

- `FactRuling.verdict` 三态：**确有其事 / 断章取义 / 无法判定**
  （2026-10-07 括注：当日起补「不实」成四态，见上线手册未决 #16）
- `FallacyKind` 四类话术：**时间错配 / 断章取义 / 张冠李戴 / 数字夸张**

## 2 逐格比对：三个阶段各差什么

| 现有能力 | 阶段一 · 普法 | 阶段二 · 舆论预防 | 阶段三 · 法律初诊 |
|---|---|---|---|
| 煽动性识别 | ◐ 只评估给定文本，不讲解法条 | ● 直接可用 | ○ 与我的处境无关 |
| 危害评估 | ◐ 可当反面案例 | ● 直接可用 | ○ 与我的处境无关 |
| 网络裁判 | ◐ 四类话术可做教学素材 | ● 四类话术**正中靶心** | ◐ 能判造谣与断章，但不能给建议 |
| 图像鉴伪 | — 不涉及 | ◐ 引擎已就绪但未注册 | ● 正对「假证」场景 |
| 主控汇总 | ○ 契约里没有任何普法字段 | ◐ 需从裁判转向当事人 | ○ 契约里没有任何初诊字段 |

● 可直接复用　◐ 引擎可用但需转向/有条件　○ 目前没有　— 不涉及

### 结论：**「三部分所用智能体基本相同」这个判断不成立**

逐阶段核对后的实际情况是：

| 阶段 | 复用率 | 说明 |
|---|---|---|
| 二 · 舆论预防 | **高** | 引擎和话术清单都对得上，只缺"转向" |
| 三 · 法律初诊 | **低** | 现有 4 项里 3 项与"处境评估"无关，只有图像鉴伪用得上 |
| 一 · 普法 | **很低** | 现有能力全是"评估给定文本"，没有一个是"讲解法律规定" |

原因不难看清：**现有 Partner 全部是「评估器」——输入一段言论、输出对它的评价**。
而普法要的是「讲解器」，第三阶段要的是「顾问」。这是三类不同的东西。

## 3 三个结构性发现

### 3.1 视角是反的：现在是**第三人称裁判**，你要的是**第一人称当事人**

| | 现在 | 你要的 |
|---|---|---|
| 输入 | 别人发的一段言论 | 我自己遇到的事 |
| 输出 | 这段话危害几分 | 我这事属哪种性质 |
| 结论给谁 | 平台、公权力机关 | 给我，告诉我下一步怎么走 |
| 建议口径 | **明确禁止**建议用户采取行动 | **必须**给：该不该找律师、找哪类 |

这不只是措辞问题。`harm_index` 这个主指标在语义上就是「对**第三方言论**的评价」，
它**装不下**「我这处境的严重程度」——两者的主语不同。

更直接的冲突在提示词：那句"不要直接建议用户采取任何行动"是**为了合规**写的
（避免 AI 给出法律意见）。而你第三阶段的要求正好相反。
要同时成立，不能靠删掉那句话，只能**新增一份契约**（见 §4）。

### 3.2 三阶段是**需求叙事**，不是**创新性叙事**

比赛评分细则里有一句是决定性的：

> 「仅简单复用开源示例代码，无自主创新改造，方案**同质化严重**，得 0-8 分」（创新性，满分 25）

而 `赛道策略分析.md` §四已记录过判断：**「换个场景」不算创新，协同交互机制的设计才算。**

所以要特别提醒一件事：**把三个阶段写进材料是加分项，但它加的是「需求分析 10 分」和「应用成效 10 分」，不是「创新性 25 分」。**
如果材料里试图用"我们能服务三个阶段"去论证创新性，评委会看到的是"一个法律场景的 leader + partner"——恰恰命中那句"同质化"。

创新性的位置在**机制**上，而你已经有的机制是：委托链证据留存、链深熔断 + 环检测、
身份闸门（`DebateChainGuardHooks` 拦外部团队 Agent）、两级嵌套 Leader–Partner 结构。
**三阶段应该用来给这些机制提供"为什么必须这么设计"的动机，而不是顶替它们。**

### 3.3 真正能跨阶段复用的只有 **2 个**，而它们恰好是你最独特的资产

- **`fact-judge` 的四类话术 + 三态裁定** —— 这就是你说的"造谣、污蔑、断章取义"的
  可计算版本。而且「断章取义」这一条正是**你自己遭遇**的核心。
  别的团队做法律 Agent 不会有这个清单，因为它来自具体经历。
- **`evidence-image`** —— 对应第三阶段"被假证造谣"里的"假证"。

**判断**：从叙事价值看，这条比"三个阶段"更强：
「一个被断章取义过的人，做了一个能把断章取义拆成可核查话术的系统」——
这是真实、独特、能打动评委的故事，而且**已经有代码支撑**。

## 4 建议的架构形态：一个引擎 + 三个入口

现状是「一个 Leader 通吃、一份契约」；你的三阶段需要的是：

```
        ┌──────────────── 共享能力层（Partner 池，基本不变）────────────────┐
        │  incitement · harm · fact-judge(±辩手) · evidence-image          │
        └────────────────────────────┬────────────────────────────────────┘
                                     │  被三个入口分别委派
        ┌────────────────────────────┼────────────────────────────────────┐
        ↓                            ↓                                    ↓
  入口 A · 法律意识              入口 B · 舆论维权                  入口 C · 法律初诊
  契约：情境 + 法律规定 + 边界    契约：话术命中 + 证据固定 + 路径    契约：事态类型 + 程度 + 律师领域 + 下一步
```

**为什么是三个入口而不是一个**：

1. 三个阶段的输出结构**互不重叠**（普法要素 / 维权要素 / 初诊要素），
   硬塞进一份 `FinalVerdict` 只会让每个字段都变成可选、等于没有契约。
2. 从比赛角度，**三个 Leader 各自委派同一批 Partner** 比单链更能体现
   「跨智能体协同」「多智能体调度」——正是赛题鼓励方向②，也能让创新性叙事落地。
3. 现有嵌套结构（裁判自己也是个 Leader）已经证明了这套模式可行，
   新增入口不需要动底层。

**同时必须守住的两条**：

- **不要为了三阶段去改已过审角色的 ACS**。本次核对确认：只动 instructions 与注释时，
  6 个已过审角色的作者可控字段指纹**一字未变**（`name/description/version/skills/...`）。
  新增入口 = 新增 Agent = 新增审核，**不动老的**。
- 三个入口都要**继续带 `disclaimer`**，并沿用现有的证据分级（一手材料 / 二手转述 / 观点评论）。

## 5 第三阶段有一个真实的合规边界，必须提前设计

**「建议找哪些律师」这句话里藏着一条线。**

- ❌ 如果输出「推荐 XX 律所 XX 律师」→ 接近律师推介，可能触及执业管理规定
- ✅ 如果输出「这类问题通常属于**名誉权 / 网络侵权 / 刑事自诉**范畴，可咨询该领域的执业律师」→ 这是**路径信息**，不是法律意见

**建议**：第三阶段给的是**专业领域**，不是具体律师。同时把动作建议写成
「你现在可以先固定下来的三类证据」这种**可执行但不越界**的形式。

参考领域分类（网络造谣诽谤场景，供设计契约时用；具体以执业律师判断为准）：

| 可能的定性方向 | 对应的律师领域 |
|---|---|
| 民事名誉权纠纷 | 人格权 / 名誉权，网络侵权 |
| 刑事诽谤（多为自诉案件） | 刑事自诉、刑事辩护 |
| 治安管理处罚范畴 | 行政法、行政复议与诉讼 |

⚠️ 这条边界**必须写进入口 C 的提示词**，不能只靠模型自觉——
这正是本项目一贯的做法（把安全约束做成结构，而不是纪律）。

## 6 优先级建议（结合 10-15 截止，今天 10-01）

比赛的两个刚性约束（引自 `初步得分评估.md`）：

- **P0 一票否决线**：平台「注册 → 发现 → 互联 → 访问」四步必须走完并存证。
  这条**不占 110 分**，但没走完 110 分全部作废。
- **P1 单笔最大涨幅**：创新性（现约 4/25），靠多跳委托与自主机制。

**三阶段的建议实施顺序是 ② ＞ ③ ＞ ①，不是 ① ② ③。** 理由：

| 顺序 | 阶段 | 为什么在这个位置 |
|---|---|---|
| 1 | **② 舆论预防** | 唯一「引擎已备、只差转向」的阶段；同时天然构成"同一批 Partner 被多入口调度"，直接喂给创新性叙事；又正好是你个人经历的核心 |
| 2 | **③ 法律初诊** | 真空最大（现有 4 项能力 3 项无关），补上它"完整度"提升最明显；但它需要新建能力，排在②之后 |
| 3 | **① 普法** | 需要一套全新的"讲解型"能力，投入产出比最低；且"普法问答"本身同质化风险高，不容易讲出新意 |

**建议**：把 ① 在第一版里写成"**由 ② 顺带覆盖**"——用户问"网上骂人算不算犯法"，
现成的 `fact-judge` + `legal_hints` 就能答一部分，不必单开一个入口。
等 ② ③ 落地后再决定 ① 要不要独立。

## 7 一句话总结

**你的三阶段是一次精准的**需求梳理**，但它同时暴露了两件事：**
**一是现有系统的视角（裁判第三方）与你真正想服务的场景（当事人第一人称）是反的；**
**二是"三个阶段共用同一批 Agent"在能力上只对第二阶段成立。**

**最有价值的动作不是新增功能，而是把 `fact-judge` 已经有的四类话术与三态裁定，
从"评价别人"转向"保护自己"——那既是你的经历，也是这个项目最难被复制的地方。**
