## 0 一句话

**你扮演 AIP 里的「Leader」，向「法律咨询主控」发一个带文本（必要时带图片或录音）的任务；
它自己去调度内部专家，最后交回一份 `FinalVerdict` 结构化结论。**

你**只需要**跟法律咨询主控打交道。内部那些 Agent 是它的下属，不是你的。
（名单与端口见 §5.1 —— 那里是**唯一**的对外清单，别在别处再抄一份。）

## 1 先厘清三个称呼 —— 这里最容易讲错

| 称呼 | 指谁 | 说明 |
|---|---|---|
| **AIP 的 Leader** | **你（调用方）** | 规范原文：*「领导者是指发布任务并组织交互的智能体」*（规范 §3.1） |
| **法律咨询主控** | 你要调的那个 Agent | 你自己系统里的 Leader，端口 8445 |
| **它的 Partner** | 煽动性识别 / 危害评估 / 网络裁判 … | 你**不直接调**它们 |

⚠️ **同一个词「Leader」在两个层面含义相反**：在 AIP 里你是 Leader，在业务架构里它才是 Leader。
对外介绍时建议说「**调用方**」和「**法律咨询主控**」，避免听众混淆。

## 2 谁有资格调用

**调用方应当是一个已注册的 ACPs Agent**，而不是裸的 HTTP 客户端。依据（规范 §6.0）：

- 直连模式在 `identity_binding_enabled=true` 时，接收方**必须**从 mTLS 对端证书里取 AIC，
  并校验 `senderId == peer AIC`；不一致返回 `AuthorizationFailedError (-32009)`
- 也就是说：你请求里填的 `senderId`，必须与**你发起连接所用的客户端证书**里的 AIC 一致

⚠️ 该开关的实际取值由部署方决定，**本项目没有验证过它在平台上的当前状态**。
但无论开关如何，**先拥有自己的 AIC 都是前提** —— 协议里的 `senderId`、mTLS 身份、
以及"谁发起过这次任务"的追溯都挂在它上面。

结论：**调用方自己也得起一个 Agent、完成注册拿到证书**。人不能直接对着端口说话，
得通过你那个 Agent、或平台提供的前端。

## 3 说什么话

输入就是任务命令里的**文本**（`dataItems` 里的 `text` 项）。法律咨询主控的
`LEADER_INSTRUCTIONS` 定义了三条受理分支，**你的措辞决定走哪一条**：

### 3.1 标准研判（永远会跑）

不管你怎么说，煽动性识别与危害评估这两步都会执行。最省的写法：

```
请研判下面这段言论是否有煽动性、社会危害性处于什么档位：

「<把原文逐字贴上>」
```

### 3.2 加「事实核查 / 辩论」分支

**触发词**：事实核查、辨真伪、谁在造谣、发起辩论。**必须明确说出来**，否则不会走。

```
请研判下面这段话，并做事实核查、辨明真伪：

「<原文>」
```

主控会把事件派给「网络裁判」，裁判自己组织正反双方辩论并出裁定书。

### 3.3 加「图像鉴伪」分支

**触发词**：有没有被改过 / 剪辑痕迹 / 是不是拼接的。**同时必须随任务带上图片**。

```
请研判这段言论，并检查随图有没有篡改或拼接的痕迹：

「<原文>」
```

### 3.4 加「录音鉴伪」分支

**触发词**：这段录音有没有被剪过 / 是不是拼接的 / 有没有编辑痕迹。
**同时必须随任务带上音频文件。**

```
请研判这段言论，并检查随附的录音有没有剪辑痕迹：

「<原文>」
```

⚠️ 录音这一支有两条与图片**不同**的地方，说清它们能省掉一轮往返：

- **音频没有"地址"这条路**。图片可以给一个地址（在白名单内时系统会去取），
  音频**只接受字节**（任务附件产生的 `inbox:<sha256>` 句柄，或内联 base64）。
  你手上**只有地址**的话，请把录音**作为附件**重新发一次，别指望它去取。
- **「无法判定」在音频上出现得更频繁**。服务器上没有 ffmpeg / sox / librosa，
  MP3/AAC 这类压缩格式解不出波形；手机在户外录的音通常测不到市电痕迹。
  **这是如实报告，不是故障** —— 但也正因为常见，转述时更要小心，
  别把"没测"说成"没事"。

### 3.5 措辞上要注意的

- **说清你要哪几件事**。主控只做它被要求做的分支，不会替你推测意图。
- **不要指挥它去调哪个内部 Agent**。它的 instructions 明确禁止跨层调用
  （AIP §3.2：Partner 之间不直接交互），你越权指挥只会白烧轮次。
- **原文要逐字贴**。主控的结论里会逐字引用被研判文本（`FinalVerdict.subject`）。
- 它会输出**辅助研判**，不会给你「构成犯罪」这类定性 —— 这是设计使然，不是失败。

## 4 什么文件能带、怎么带

### 4.1 实测出来的边界（这是重点）

| 你发的附件 | AIP 转成 | 系统接住了吗 |
|---|---|---|
| 图片 `image/png`、`image/jpeg` … | `ImagePart` | ✅ **完整支持**（登记 + 给句柄 + 能转给下游） |
| 音频 `audio/*` | `AudioPart` | ✅ **完整支持**（登记 + 给句柄 + 能转给下游；见下面的口径） |
| 视频 `video/*` | `VideoPart` | ⚠️ 会进模型请求，但**系统不登记、也不转给下游** |
| PDF / txt / md / json / 未知类型 | `FilePart` | ⚠️ 同上 |

实测口径（`wit.acps.aip.data_item_to_content_part`，逐类跑过）：
MIME 以 `image/` 开头走 `ImagePart`，`audio/` 走 `AudioPart`，`video/` 走 `VideoPart`，
**其余一律走 `FilePart`**。三种 DataItem 的对应关系是
`text→TextPart`、`data→DataPart`、`file→FilePart`。

⚠️ **音频的"完整支持"要按这个口径读**：登记、转交下游这两件事已接线（2026-10-02 起），
但**能不能出结论取决于格式**：WAV/PCM 能解出波形、九项全跑；
MP3/AAC/FLAC/OGG 因为本机没有解码器**只能给容器与编码参数层的结论**，
报告里会以「波形可用：否」和一段材料级弃权如实写出。
**这不是没接线，是这条链必须如实说出的能力边界。**
（音频的能力细节与用法见同目录的《音频鉴伪使用说明.md》。）

**现在有两条完整通道：图片与音频**；视频与其它类型仍然没有下游通道 ——
这条正是**只有鉴伪链做了完整接线**（因为鉴伪专家需要字节）。

### 4.2 三条送法

**(a) 内联字节** —— 最可靠，不依赖网络

```json
{ "type": "file", "name": "x.png", "mimeType": "image/png", "bytes": "<base64>" }
```

**(b) 外链** —— 系统**不会自动去取**，而且目标主机必须在白名单里。
⚠️ **只对图片有效**：音频侧**没有任何出网通道**，给了地址一定取不到。

```json
{ "type": "file", "name": "x.png", "mimeType": "image/png", "uri": "https://…/x.png" }
```

服务端需设 `EVIDENCE_IMAGE_ALLOWED_HOSTS=<逗号分隔主机名>`，否则会**如实拒绝**
（并给出补救建议）。这是刻意的：一张入站图里塞个 URL，不该等于一次自动出网。

⚠️ `uri` 与 `bytes` **互斥**，二选一（规范 §4.7 原文：*与 bytes 字段互斥使用*）。

**(c) 本地路径** —— **服务模式读不到**，只在单机自测时可用，不要写进对外说明

### 4.3 建议

- **图片** → 用 `bytes`（内联）。最省事，也不受白名单影响。
- **音频** → 用 `bytes`（内联）或附件句柄。**音频没有外链这条路**，
  给地址只会收到一条"不支持的引用"。
- **文字材料**（合同、长文公告等）→ **直接把文字贴进 `text`**，
  不要作为文件发。因为 `FilePart` 目前没有下游通道，发过去等于没发。
- 若确实需要提交 PDF，**先自行转成文本**再贴进 `text`。

## 5 怎么调用

### 5.1 平台 / 协议方式（正式路径）

一次 JSON-RPC 调用，HTTP POST 到主控的端点：

```
POST https://150.109.154.16:8445/rpc
Content-Type: application/json
（走 mTLS，客户端证书用你自己的 AIC）
```

请求体：

```json
{
  "jsonrpc": "2.0",
  "method": "rpc",
  "id": "1",
  "params": {
    "command": {
      "type": "task-command",
      "id": "msg-<uuid>",
      "sentAt": "2026-10-01T18:00:00+08:00",
      "senderRole": "leader",
      "senderId": "<你自己的 AIC>",
      "command": "start",
      "taskId": "task-<uuid>",
      "sessionId": "session-<uuid>",
      "dataItems": [
        { "type": "text", "text": "请研判下面这段言论是否有煽动性、社会危害性处于什么档位：\n\n「…原文…」" }
      ]
    }
  }
}
```

带图片时，在 `dataItems` 里追加：

```json
{ "type": "file", "name": "x.png", "mimeType": "image/png", "bytes": "<base64>" }
```

## 6 你会拿回什么

**当次 RPC 的响应**就是一个 `TaskResult`，状态可能是：

| 状态 | 含义 | 你该做什么 |
|---|---|---|
| `accepted` | 收下了，稍后开工 | 发 `get` 或 `wait` 等结果 |
| `working` | 正在干 | 同上 |
| `awaiting-completion` | **干完了**，`products` 里有产出物 | 看 products；满意就发 `complete` |
| `rejected` / `failed` | 明确失败 | 按错误信息处理 |

**最终产物**是一份符合 `FinalVerdict` 契约的 JSON：

| 字段 | 含义 |
|---|---|
| `subject` | 被研判的原文（逐字引用） |
| `harm_index` | 社会危害性指数，`-100..100`（**正数=有问题，负数=正当**） |
| `band` | 由 `harm_index` 自动映射的档位名 |
| `is_incitement` | 是否认定构成煽动性言论 |
| `truth_score` | 为真程度 `0..100` |
| `consistency_note` | 两位专家结论冲突时的取舍理由（含图像/音频技术线索、裁定要点） |
| `conclusion` | 面向普通用户的通俗结论 |
| `action_advice` | 克制措辞的建议 |
| `disclaimer` | 免责声明（固定带上） |

⚠️ **注意量表方向**：这是**双极**刻度，不是"越大越严重"的单向分。
`+81~+100` 涉嫌违法，`0` 中性，`-100~-61` 属受法律保护的正当言论。
按颜色直觉理解会读反。

产物同时**落盘在服务端**：`output/verdict-<UTC时间戳>.json`。

## 7 已知边界（对外说明时别漏）

1. **Discovery 索引当前异常**：本账号自己的 Agent 在 Discovery 里**一条都召回不到**
   （registry 侧 6/6 是 `APPROVED/active`）。这会让"主控去 discover 自己的 Partner"
   这一步失败。**这是平台侧问题，不是本系统的 bug**，恢复前平台端到端调不通。
2. **证据链三个角色尚未登记注册信息**：`evidence-leader` / `evidence-image` /
   `evidence-audio` 本机都只有 `acs.draft.json`，没有 `enrollment.json`。
   所以 §3.3 与 §3.4 那两条分支目前会走到"找不到专家"。
   （⚠️ 音频的 **MCP 通道不受影响** —— 它不需要注册，见《音频鉴伪使用说明.md》。）
3. **附件完整支持的模态是图片与音频**（见 §4.1）。**视频与其它类型没有下游通道。**
4. **音频的能力边界（如实说，别当成 bug）**：本机没有 ffmpeg / sox / librosa，
   压缩格式（MP3/AAC/FLAC/OGG）**解不出波形**；手机在户外录的音**通常测不到**
   市电痕迹。所以音频链上「无法判定」是常态 —— 报告会如实写出来，
   转述时**不要**把它说成「没问题」。
5. **文件名/主机白名单**：外链图片必须命中 `EVIDENCE_IMAGE_ALLOWED_HOSTS`。
   **音频没有外链这条通道**（只接受附件句柄或内联字节）。
6. **主动出网是被禁的**：系统不会因为你在图里塞了个 URL 就去抓取。

## 8 一张最小的对照卡

| 你想做的事 | 你说什么 | 你给什么 |
|---|---|---|
| 判断一段话有没有问题 | 「请研判…是否有煽动性、社会危害性处于什么档位」+ 原文 | 文本 |
| 判断是不是谣言 | 加上「并做事实核查、辨明真伪」 | 文本 |
| 判断图片有没有被 P 过 | 加上「检查随图有没有篡改或拼接痕迹」 | 文本 + **图片字节** |
| 判断录音有没有被剪过 | 加上「检查随附录音有没有剪辑痕迹」 | 文本 + **音频字节** |
| 提交一份长材料 | 把材料文字贴进文本里 | 文本（**不要**发 PDF） |

## 9 想直接用鉴伪能力、不想起 Agent？

鉴伪这条链**另有一个 MCP 入口**：本机进程、stdio、不需要注册与证书，
面向"想把这套检测能力接进自己工具箱"的人。

配置与用法见 **[《音频鉴伪使用说明.md》](./音频鉴伪使用说明.md)**。
一句话：把项目 `.venv` 的 python 绝对路径 + `-m legal_acps.mcp.server` + 项目根目录
写进客户端的 `mcpServers` 配置即可。
